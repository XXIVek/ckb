===SUMMARY
Первая карточка слоя правил MCP `1c-configurations-enrichment` — уровень 2 дерева правил. Она говорит, что это за сервер и
как устроены правила его слоя; сами правила лежат следующим уровнем.

Сегодня правила слоя записаны под прежним адресом `enrich-rules:<...>` — слой ещё не переразвёрнут в
дерево `rules:enrich-rules:<правило>`. Поэтому перечень `===LINKS` ниже ведёт именно туда, а
подсказка «когда нужен» взята из раздела `===WHEN` самой карточки. Когда слой переразвёрнут,
ссылки переставляются на адреса дерева в тот же момент, когда меняется строка БД.

Раздел `===MCP` — общие записи слоя, перенесённые из корневой карточки без правок текста. Их разбор
по отдельным правилам и частям `ref:NNN` — отдельный шаг.

===MCP
### 🔄 Шаг 3: Анализ и обогащение объектов выгрузки (MCP `1c-configurations-enrichment`)

**Когда использовать:** посмотреть, что представляет собой загруженный внешний отчёт и что делает его
код; найти объект по русскому синониму, имени реквизита, элемента формы, имени процедуры; создать
или снять алиас/сниппет/ссылку на документацию. Полные правила —
`.clinerules/1c-configurations-enrichment_Rule.md` (контракт — 21 инструмент).

| Сценарий | Инструмент | Описание |
|----------|-----------|----------|
| **Карточка объекта:** | | |
| Свойства, состав, что делает код | `config_enrichment_stats_tool(uuid?, limit=20, card=True)` | без `uuid` — сводка по всем объектам (в т. ч. раздел «ПРИВЯЗКИ К КОНФИГУРАЦИИ»: заголовки и число привязанных объектов, счётчики состояний); с `uuid` — карточка: свойства, синоним, реквизиты с типами, ТЧ, формы и их состав, макеты, модули, сниппеты, состояние привязки |
| **Привязка к конфигурации (узлы V20/V20.1):** | | |
| Заявить или снять привязку | `set_object_configuration_tool(uuid?, source_path?, configuration_id?)` | `configuration_id` — id строки заголовка `configurations.id` (НЕ uuid метаданных 1С); `None` — снять; несуществующий или нечисловой id отклоняется, привязка не меняется; возвращает «было/стало», имя и версию заголовка и число привязанных объектов |
| **Состав макета-СКД (узел B):** | | |

| **Генерация:** | | |
| Пересобрать алиасы и сниппеты | `generate_config_enrichment_tool(uuid?, source_path?)` | источник — сохранённое содержимое БД, конфигуратор не открывается |
| **Алиасы:** | | |
| Найти алиас по началу/середине | `search_config_aliases_tool(query, uuid?, target_type?, limit?)` | так работает поиск по алиасам |
| Разрешить алиас точно | `resolve_config_alias_tool(alias)` | отдаёт цели (объект, реквизит, форма, элемент, макет, модуль, сниппет) |
| Список алиасов объекта | `list_config_aliases_tool(uuid?, target_type?, origin?, limit?, include_inactive?)` | `origin`: `generated` / `manual` |
| Добавить ручной алиас | `add_config_aliases_tool(aliases, uuid?, source_path?, target_type?, target_name?, ...)` | там, где термина нет в выгрузке (русские формулировки, аббревиатуры) |
| Снять алиас | `delete_config_alias_tool(alias_id, hard=False)` | по умолчанию мягкое снятие (`active=false`) |
| **Сниппеты:** | | |
| Полный код + зависимости + алиасы | `get_config_snippet_tool(snippet_id)` | карточка сниппета |
| Список сниппетов (без кода целиком) | `list_config_snippets_tool(uuid?, source_kind?, limit?, only_verified?, include_marked=False)` | код бывает десятки КБ; помеченные к удалению скрыты по умолчанию |
| Полнотекстовый поиск по сниппетам | `search_config_snippets_tool(query, uuid?, limit?, include_marked=False)` | ищет и вопрос, и код; карантин скрыт по умолчанию, по `include_marked=True` отдаётся с явной пометкой и в конце выдачи |
| Что известно про конкретную цель | `get_config_snippets_for_object_tool(uuid?, source_path?, target_type, target_name, include_marked=False)` | перед тем, как писать новый сниппет |
| Добавить ручной сниппет | `add_config_snippet_tool(question, answer, uuid?, source_path?, dependencies?, ...)` | `is_verified=true`, обязан сослаться на сохранённую цель |
| Удалить сниппет | `delete_config_snippet_tool(snippet_id)` | снимает и его алиасы, зависимости, ссылки |
| **Карантин сниппетов (узел Q1, 16.10.2026)** | | |
| Пометить ошибочный сниппет на удаление | `mark_config_snippet_tool(snippet_id, reason?)` | строка остаётся в БД, выдача её не отдаёт; причина — второй тег `mark-for-deletion:reason=…` |
| Снять пометку | `unmark_config_snippet_tool(snippet_id)` | возвращает строку в поиск, списки и карточку объекта |
| Разобрать карантин перед чисткой | `list_marked_config_snippets_tool(uuid?, limit=50)` | id, объект, вопрос, источник, `is_verified`, причина; физически снимает только `tools/purge_marked_snippets.py` (`--dry-run` по умолчанию) |
| **Связи с документацией:** | | |
| Поставить указатель `local_doc` → цель | `add_config_cross_reference_tool(uuid?, local_doc_kind, local_doc_id, target_type?, ...)` | битый id не сохраняется |
| Прочитать связи | `get_config_cross_references_tool(uuid? \| local_doc_id, limit?)` | с проверкой указателя в `local_doc` |
| Снять связь | `delete_config_cross_reference_tool(reference_id)` | |

**Перед началом редактирования файлов MCP `1c-configurations-enrichment`:**

```text
C:\1C_LLM\ckb\.clinerules\1c-configurations-enrichment_Rule.md
```

**Что нужно знать из файла правил:**

- Структура обогащения `ckb_1c_configurations`: `config_aliases`, `config_snippets`,
  `config_snippet_dependencies`, `config_cross_references`, витрины `v_config_alias_targets`,
  `v_config_enrichment`
- Словарь `target_type` (`ExternalReport`, `Attribute`, `TabularSection`, `TabularSectionColumn`,

- Правила удаления: алиас — мягкое снятие, сниппет — hard с его алиасами/зависимостями/ссылками,
  enrichment чистится и при удалении самого объекта

### 🎯 Словарь `target_type` (цели алиасов и зависимостей)
| `target_type` | Где цель | `target_uuid` |
|---|---|---|
| `ExternalReport` / `ExternalProcessing` | строка `external_report` любого вида (узел V22): вид различает колонка `object_kind`, отдельной таблицы `external_processing` в схеме нет | `uuid` строки заголовка; тип цели обязан совпадать с видом объекта |
| `Attribute` | `attributes` (реквизит объекта) | `attributes.uuid` |
| `TabularSectionColumn` | `attributes` (колонка ТЧ) | `attributes.uuid` |
| `TabularSection` | `tabular_sections` | `tabular_sections.uuid` |
| `Form` | `forms` | `forms.uuid` |
| `FormItem` | `form_ext.items` | `form_item:<uuid формы>:<имя элемента>` |
| `Template` | `templates` | `templates.uuid` |
| `Module` | `bsl_modules` или `form_ext.ext` | `module:<bsl_module_id>` / `module:form:<uuid формы>` |
| `ConfigSnippet` | `config_snippets` | `snippet:<id>` |
| `Configuration`, `Catalog`, `Document`, … | таблицы объектов конфигурации | ❌ варианты загрузки 1–2 не реализованы, типы зарезервированы |
| элементы макета-СКД (типы `DataSet`, `DCSParameter` … зарезервированы, целей в `config_aliases` нет) | содержимое `templates.ext` (узел B) | `dcs:<uuid макета>:<kind>:<имя>` — ключи отдаёт `src/enrichment_dcs.py::dcs_target_key` |

Правило: новый `target_type` появляется только вместе со строкой таблицы-цели и проверкой в
`validate_enrichment_flow.py`. Элемент формы принимается и в qualified-виде `<форма>.<элемент>`
(так его отдаёт `v_form_elements`), и голым именем — оба варианта ведут в один `form_item:`-ключ.
Модуль формы — цель `Module` с именем формы: он хранится в `form_ext.ext`, а не в `bsl_modules`.
С узла E цель `Module` принимается в обеих записях одной цели — именем формы (`Module:Отчет`,
как в `dependencies`) и qualified-видом `Form.<ИмяФормы>` (как `target_name` алиаса); резолвер
снимает префикс `Form.` и разрешает обе в `module:form:<uuid формы>`.
Адресация цели в инструментах — тройка `target_type` / `target_name` / `target_uuid`
(для цели на сниппет — `target_snippet_id`); тот же формат `target_uuid` читают витрины.


##### id=6073 enrich-rules:ref:08 tags=['1c-configurations-enrichment', 'enrich-rules', 'rules-layer', 'ref']
### ⚠️ Критические правила
1. **Объект адресуется uuid или путём выгрузки.** `uuid` — uuid строки `external_report`
   (любого вида: `object_kind` = `external_report` или `external_processing`, узел V22),
   `source_path` — каталог выгрузки; достаточно одного. `config_id` в этих
   инструментах нет и не появится.
2. **`delete_config_alias_tool` — мягкое снятие** (`active=false`): строка видна в истории,
   поиск её не отдаёт, перегенерация не восстанавливает и не удаляет. `hard=True` — убрать
   ошибочный ручной алиас совсем.
3. **`delete_config_snippet_tool` — hard-delete**: вместе со сниппетом снимаются его алиасы,
   зависимости и `documentation`-ссылки, сирот в `config_aliases` не остаётся. В ответе видно
   число снятых строк каждой таблицы и предупреждение для авто-сниппета (следующая генерация
   создаст его заново из сохранённого кода; ручной `is_verified=true` — не создаст).
4. **Дубликаты не создаются**: алиасы — `ON CONFLICT DO NOTHING`; зависимости сворачиваются по
   стабильному ключу цели; `add_config_snippet_tool` опознаёт существующий авто-сниппет по
   `source_uuid` + имени объявления и **дописывает** к нему вручную указанное поведение, а не
   создаёт второй экзепляр.
5. **Несуществующая цель — отказ**, а не связь вникуда: цель зависимости обязана существовать
   в сохранённом содержимом объекта; указатель `local_doc` проверяется в базе `local_doc`.
6. **Поиск по алиасам**: `search_config_aliases_tool` ищет по началу и середине термина
   (`prefix` + подстрока, как `alias_targets` в `local_doc`); точное совпадение —
   `resolve_config_alias_tool`. Неактивные алиасы не отдаются нигде, кроме
   `list_config_aliases_tool(include_inactive=True)`.
7. **Ручные алиасы нужны там, где термина нет в выгрузке**: русские формулировки, аббревиатуры,
   английские термины — автогенерация их не покрывает (итоговый раздел `check_external_report_search.sql`
   фиксирует покрытие по каждой эталонной выгрузке).
8. **Правки Python-кода требуют перезапуска сервера**: `cd C:\1C_LLM\ckb; python server_configurations_enrichment.py`.
   Правки документов и SQL перезапуска не требуют.
9. **Ручные алиасы и указатели на documentation — обязательная часть процесса, а не услуга
   оператору.** Сразу после `generate_config_enrichment_tool` и до выдачи анализа, без
   предварительного вопроса:
   - `add_config_aliases_tool` — русские формулировки, аббревиатуры («СКД», «90.02»), термины
     предметной области, которых нет в выгрузке; цели — сам объект, его ТЧ, макет, модуль;
   - `add_config_cross_reference_tool` — по найденным в `1c-knowledge-base` группам
     (`search_docs_tool` коротким термином: `СхемаКомпоновкиДанных`, `ПроцессорКомпоновкиДанных`,
     `КомпоновщикМакетаКомпоновкиДанных`, `РеквизитФормыВЗначение`, …) на цели `Template`,
     `Module`, `Form`, `ExternalReport`.

   **Критерии T1–T3 (приняты 14.10.2026): ссылка ставится, только если выполнены все три.**
   - **T1 — якорь на конкретный фрагмент.** Цель — то место, где поведение реально есть:
     `Template` (макет СКД), `Module` (модуль формы/объекта), `Form`, конкретный сниппет.
     Ссылка «на объект в целом» допустима, только если о поведении говорит вся карточка.
     Практическая проверка: ссылка, привязанная к `ConfigSnippet`, видна в карточке этого
     сниппета (`get_config_snippet_tool`, раздел «Ссылки documentation»); привязанная к целому
     `Module`/`Template` — в карточке сниппета не видна.
   - **T2 — только неочевидное.** Ссылка объясняет поведение или дефект, которые не выводятся
     из имени: `use=false` у параметра → пустой связанный набор; `dataSetLink` по номенклатуре
     вместо документов; дублирующий отбор `ГДЕ` поверх параметра; способ передачи данных формы
     на сервер.
   - **T3 — не дублировать типовое.** Не ставить то, что подходит любому отчёту СКД: «что такое
     СКД», «как описать поля макета», общие API-справочники. Если группа находится коротким
