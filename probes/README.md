# Круг доказательств узлов

Здесь лежат скрипты замеров узлов (`_v48_*`, `_v54_*`, …) — то, чем подтверждаются
числа и формулировки в планах `docs/*_PLAN.md` и в карточках правил. Файлы в этом
каталоге не являются инструментами работы: по ним не ходят каждый день, их читают
тогда, когда нужно восстановить, как был получен замер.

## Что сюда кладут, а что не кладут

| признак | куда |
|---|---|
| файл только печатает замер и никем не вызывается | `probes/<узел>/` |
| файл `import`-ит работающий скрипт (`tools/`, корень, `src/`) | `tools/` — это код, а не доказательство |
| файл называет командой запуска всегда читаемый `.clinerules/1C_Rule.md` | `tools/` — инструкция должна вести в рабочее место |
| на файл нет ни одной ссылки (план, проверка, правило, другой зонд) | не хранить: он ничего не доказывает |

Разделение сделано по факту ссылок, а не по имени: имя `_v48_p8_stop_probe.py` не
говорит, нужен файл или нет, — говорит ссылка норматива на него.

## Как запускать

Каталоги узлов не добавляются в путь поиска Python сами. Зонд, который работает от
текущей папки (`sys.path.insert(0, "src")`), запускается из корня репозитория:

```powershell
python probes/v48/_v48_p8_stop_probe.py
```

Зонд, который ищет модули от своего файла, поднимается на два уровня вверх
(`Path(__file__).resolve().parents[2]`) и потому не зависит от текущей папки.

Зонд одного узла вправе импортировать модуль другого узла (карточки правил узла V52
строятся модулем узла V48). Такой импорт требует явной строки пути:

```python
sys.path.insert(0, str(Path(__file__).resolve().parents[2] / "probes" / "v48"))
```

## Почему карточки правил называют файлы коротким именем

Карточка записиывает замер так, как он выглядел в день замера. Переписывать историческую
строку новым путём — значит стирать сам замер. Поэтому и `_named_artifacts_audit.py`, и
`rules_layer.artifact_exists` резолвят голое имя `_x.py` по кругу доказательств
(`probes/*/x.py`), а не сравнивают его с одним каталогом. Вопрос остался прежним:
существует ли названный файл.

## Граница каталога

- `probes/misc/` — файлы без номера узла: правки правил, замеры состояния, общие модули.
- `probes/vNN/` — файлы узла `VNN`; узел создаёт каталог при первом же переносе.
- Вывод замеров (`.txt`, `_v54_raw/`, `logs/`) в каталог не входит и не индексируется.
