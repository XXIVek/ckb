
# Правила загрузки документации в 1C Knowledge Base

## СТРУКТУРА БАЗЫ ДАННЫХ local_doc (актуально на 07.10.2026)

| Таблица | Назначение | Что хранить |
|---------|-----------|-------------|
| groups | Группы справки (иерархическая структура, BSL-объекты) | name, parent_id, description, tags, **pagetitle**, **title**, **versionInfo**, **heading** |
| knowledge_snippets | Сниппеты кода (вопрос-ответ с примером) | question, answer, source_url, tags, confidence, groups_id (**nullable**), is_verified |
| alias_targets | Связи алиасов с группами/сниппетами | alias_name, target_type ('group'/'snippet'), groups_id (**nullable**), snippets_id (**nullable**), tags (text[]), **weight** |
| doc_categories | Категории документации | code, name, description |
| doc_tags | Теги классификации | code, name, description, weight |

> **Важно:** Алиасы могут быть привязаны к `groups_id` (для BSL-групп) или напрямую к `snippets_id` (для HTML/PDF/Markdown без групп). При поиске алиас находит и то, и другое. Вес алиасов: 1.2 (биграммы), 1.0 (title), 0.9/0.7 (heading).

## ИСТОЧНИК ДАННЫХ ДЛЯ ЗАГРУЗКИ

Путь к каталогу с файлами указывается пользователем в задании на загрузку. Файлы хранятся во внешнем каталоге C:\1C_LLM\LoadDoc, а не в проекте (объем ~50 000+ HTML + 53 PDF ~1 ГБ).

## КОНЦЕПЦИЯ ЗАГРУЗКИ: ДВА НЕЗАВИСИМЫХ СЦЕНАРИЯ

### Сценарий A: BSL-документация (группы → сниппеты)
**HTML-файл → Группа + Сниппет (с groups_id)**

1. Парсим HTML-файл (pagetitle, title, heading, versionInfo)
2. Создаём группу через `load_single_html_tool()` или `load_bsl_tool()`
3. Если есть код — извлекаем сниппеты через `add_snippet_tool(groups_id=...)`
4. Алиасы создаются автоматически при загрузке (привязка к groups_id)

### Сценарий B: HTML/FAQ/Markdown (только сниппеты, без групп)
**Текст → Сниппет (groups_id = NULL)**

1. Извлекаем вопрос-ответ из контента
2. Создаём сниппет через `add_snippet_tool()` **без groups_id**
3. Алиасы генерируются из question и привязываются напрямую к snippets_id
4. Поиск по алиасу находит сниппет с приоритетом rank=3.0 (выше групп)

## АЛГОРИТМ ДЕЙСТВИЙ AI ПРИ ЗАГРУЗКЕ

### Шаг 1: Анализ источника данных

- **Одиночный HTML-файл** → `load_single_html_tool(filepath, category)` (BSL-документация)
- **Директория с HTML/PDF/Markdown** → `load_doc_tool(path, category)` (BSL-документация)
- **Структура BSL (objects/ + tables/)** → `load_bsl_tool(path)` (категория всегда bsl)
- **Прямой текст (вопрос-ответ)** → `add_snippet_tool()` — с groups_id для BSL, без для HTML/PDF/Markdown

### Шаг 2: Определение категории

| Путь / Контекст | Категория | Сценарий |
|----------------|-----------|----------|
| `/html/BSL/` | `language,bsl` | A (группы + сниппеты) |
| `/html/platform/` | `platform` | B (сниппеты без групп) |
| PDF с документацией платформы | `platform` | B (сниппеты без групп) |
| Markdown-инструкция | определяется по контексту | B (сниппеты без групп) |

### Шаг 3: Загрузка

**Сценарий A (BSL):**

```text
load_single_html_tool(filepath="C:\\path\\file.html", category="language,bsl")
→ Создаёт группу с полями pagetitle, title, versionInfo
→ Если есть код → add_snippet_tool(groups_id=...)
```

**Сценарий B (HTML/FAQ/Markdown):**

```text
add_snippet_tool(
    question="Как использовать ...?",
    answer="[Пример кода]",
    source_url="путь_к_файлу",
    tags="platform,code",
    confidence=0.95
)
→ groups_id = NULL (не передавать!)
→ Алиасы привязываются напрямую к snippets_id
```

## MCP-ИНСТРУМЕНТЫ (server.py — 1c-knowledge-base)

### Загрузка документов

| Инструмент | Назначение |
|-----------|-----------|
| `load_bsl_tool(path)` | Загрузка полной структуры BSL (objects/ + tables/) |
| `load_single_html_tool(filepath, category)` | Загрузка одиночного HTML-файла (BSL) |
| `load_doc_tool(path, category)` | Загрузка документов из директории (.html, .pdf, .md) |
| `add_snippet_tool(question, answer, source_url?, tags?, confidence?, groups_id?)` | Добавить вопрос-ответ с кодом (**groups_id = NULL** для HTML/FAQ/Markdown) |

### Поиск и получение данных

| Инструмент | Назначение |
|-----------|-----------|
| `search_docs_tool(query, category?, limit?)` | Комбинированный поиск по группам, сниппетам и алиасам |
| `get_doc_tool(doc_id)` | Получить полную группу по ID |
| `get_db_state_tool()` | Состояние БД (groups, snippets, aliases count) |
| `list_categories_tool()` | Список категорий документации |
| `detect_tags_tool(text)` | Определить теги контента |
| `add_aliases_tool(aliases, groups_id?, snippets_id?)` | Добавить алиасы к существующей группе или сниппету |

### УДАЛЁННЫЕ ИНСТРУМЕНТЫ (НЕ ИСПОЛЬЗОВАТЬ):

- `create_group_tool`, `ensure_group_with_fields()` — заменены на `load_single_html_tool` / `load_bsl_tool`
- `batch_insert_groups()`, `batch_insert_aliases()`, `batch_insert_snippets()` — batch-вставка внутри загрузчиков
- `search_groups_fulltext()`, `search_snippets_fulltext()` — заменены на `search_docs_tool`
- `get_group_full()` — заменён на `get_doc_tool()`
- `list_groups_by_tag()` — не существует
- `search_aliases` — таблица удалена, используется `alias_targets`

### Алгоритм поиска в search_docs_tool:

1. **Поиск по алиасам (приоритет rank 3.0):** Точное совпадение alias_name (case-insensitive) → находит группы И привязанные сниппеты
2. **Приоритет прямых алиасов:** Алиас, привязанный к `snippets_id` напрямую (без группы), получает rank=3.0 > групп (rank=2.0)
3. **Full-text поиск по groups (rank 1.0):** Ищет по `name || pagetitle`. **heading НЕ участвует!**
4. **Full-text поиск по snippets (rank 0.5):** Ищет по `question || answer`
5. **Результаты сортируются по rank DESC**, limit применяется в конце.

## ФИЛЬТР ЗАГРУЗКИ: КАКИЕ ФАЙЛЫ НЕ ГРУЗИТЬ

### PDF и DOC/DOCX — строгий фильтр:

| Тип файла | Загружать? | Почему |
|-----------|-----------|--------|
| PDF со скриншотами | ❌ **НЕТ** | Текст со скриншотов = мёртвый контент без контекста, таблицы и диаграммы не конвертируются |
| DOC/DOCX со скриншотами | ❌ **НЕТ** | Изображения теряют форматирование, примеры кода на картинках бесполезны |
| Текстовый PDF (справочники, методички) | ⚠️ Осторожно | Можно грузить чанками с confidence < 0.7 и меткой источника |
| DOC/DOCX с примерами кода | ✅ **ДА** | Полезный структурированный контент с примерами BSL-кода |

### Правило принятия решения:

> **Перед загрузкой PDF/DOC — проверь, есть ли в файле примеры кода или структурированный текст.**
> Если файл содержит только скриншоты, изображения, диаграммы — **НЕ ЗАГРУЖАТЬ**.
> Ресурсы парсинга не стоят результата: сниппеты с низким confidence засорят базу.

### HTML — всегда загружать:

- BSL-документация → Сценарий A (группы + сниппеты)
- Платформа/FAQ/инструкции → Сценарий B (сниппеты без групп)

## КРИТИЧЕСКИЕ ОШИБКИ ПРИ ЗАГРУЗКЕ

- Не загружать пустые файлы без контента и служебные файлы (__categories__, каталоги)
- Для BSL: каждый HTML-файл = одна группа с полями pagetitle, title, versionInfo
- catalog213 + tables обрабатываются как единая иерархия "Работа с запросами"
- versionInfo извлекается из `<p class="V8SH_versionInfo">` — проверка совместимости платформы
- Алиасы генерируются Вариантом B: title вес 1.0/1.2, heading вес 0.7/0.9, биграммы внутри каждого источника отдельно
- **Стоп-слова для BSL отключены** — все слова > 2 символов участвуют в генерации алиасов
- Путь к файлам всегда задаётся в задании — не зафиксирован, может быть любым
- Структура папок произвольная — пример приведён только как ориентир
- **search_aliases НЕ СУЩЕСТВУЕТ** — используется `alias_targets` с полями groups_id, snippets_id, weight
- **Сниппеты без группы (groups_id = NULL)** создаются для HTML/FAQ/Markdown — алиасы привязываются напрямую к snippets_id
- **add_snippet_tool НЕ создаёт группы автоматически** — при groups_id=NULL создаётся только сниппет
