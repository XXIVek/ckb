# Правила загрузки документации в 1C Knowledge Base

## СТРУКТУРА БАЗЫ ДАННЫХ local_doc (актуально на 07.10.2026)

| Таблица | Назначение | Что хранить |
|---------|-----------|-------------|
| groups | Группы справки (иерархическая структура) | name, parent_id, description, tags, **pagetitle**, **title**, **versionInfo**, **heading** |
| knowledge_snippets | Сниппеты кода (вопрос-ответ с примером) | question, answer, source_url, tags, confidence, groups_id, is_verified |
| alias_targets | Связи алиасов с группами/сниппетами | alias_name, target_type ('group'/'snippet'), groups_id (nullable), snippets_id (nullable), tags (text[]), **weight** |
| doc_categories | Категории документации | code, name, description |
| doc_tags | Теги классификации | code, name, description, weight |

> **Важно:** Вся загрузка идёт только через **группы → сниппеты**. Алиасы привязываются к `groups_id` (для групп) или `snippets_id` (для сниппетов). Вес алиасов: 1.2 (биграммы), 1.0 (title), 0.9/0.7 (heading).

## КОНЦЕПЦИЯ ЗАГРУЗКИ (алгоритм принятия решений)

При получении задания на загрузку AI выполняет следующие шаги:

### Шаг 1: Анализ источника данных

- **HTML-файлы** — документация, справочные материалы, методы/свойства/события
- **PDF-файлы** — главы документации (Глава 4 Встроенный язык)
- **Markdown-файлы** — структурированная документация
- **Прямой текст** — вопрос-ответ, описание метода

### Шаг 2: Определение формата контента

| Признак | Методика фиксации | Инструменты |
|---------|-------------------|-------------|
| Вопрос + ответ с примером кода | Сниппет (knowledge_snippets) | add_snippet_tool |
| Структурированный документ | Группа (groups) | load_single_html_tool |

### Шаг 3: Выбор стратегии загрузки

**Сценарий A: Файлы BSL**
HTML-файл → Есть пример кода? → Да → Создать группу + сниппет Нет → Создать только группу → Привязать к родительской группе (если есть)

**Алгоритм загрузки BSL:**

1. Парсим HTML-файл (pagetitle, title, heading, versionInfo)
2. Создаём группу через `load_single_html_tool()` или `load_bsl_tool()`
3. Если есть код — извлекаем сниппеты через `add_snippet_tool(groups_id=...)`
4. Алиасы создаются автоматически при загрузке

**Сценарий B: PDF-документация**
PDF → Чанкинг по 80 страниц → Извлечение текста + кода → Создание групп → Сниппеты

## 📋 АЛГОРИТМ ДЕЙСТВИЙ AI ПРИ ЗАГРУЗКЕ

### ⚠️ ВАЖНО: Перед любой загрузкой HTML-документации

AI **обязан** определить категорию документации, прежде чем вызывать инструмент загрузки.

#### Шаг 1: Анализ источника данных

- **Одиночный HTML-файл** → `load_single_html_tool(filepath, category)` (уточнить категорию!)
- **Директория с HTML-файлами** → `load_doc_tool(path, category)` (уточнить категорию!)
- **Структура BSL (objects/ + tables/)** → `load_bsl_tool(path)` (категория всегда bsl)
- **PDF-файл** → чанкинг + загрузка через batch-вставку
- **Markdown-файлы** → import_markdown_files()
- **Прямой текст (вопрос-ответ)** → `add_snippet_tool()`

#### Шаг 2: Определение категории для HTML-документации

**Правило:** Если категория очевидна — НЕ СПРАШИВАТЬ.

| Путь / признак | Категория |
|----------------|-----------|
| `/html/BSL/` или `bsl` в пути | `language,bsl` |
| `/html/platform/` | `platform` |
| `/html/its/` | `its` |
| Неочевидный путь | **Спросить пользователя** |

Алгоритм поиска в search_docs_tool:
Поиск по алиасам (приоритет rank 2.0): Точное совпадение alias_name → находит группы И привязанные сниппеты (deduplicated по ID)
Full-text поиск по groups (rank 1.0): Ищет по name || pagetitle. heading НЕ участвует в full-text поиске — только для генерации алиасов
Full-text поиск по snippets (rank 0.5): Ищет по question || answer
Результаты сортируются по rank DESC, limit применяется в конце.

Алгоритм:

title = из <p class="V8SH_title">
heading = из <p class="V8SH_heading"> (заполнено у 22 671 из 25 495 групп)
versionInfo = из <p class="V8SH_versionInfo">

⚠️ КРИТИЧЕСКИЕ ОШИБКИ ПРИ ЗАГРУЗКЕ
Не загружать пустые файлы без контента и служебные файлы (__categories__, каталоги)
Для BSL: каждый HTML-файл = одна группа с полями pagetitle, title, versionInfo
catalog213 + tables обрабатываются как единая иерархия "Работа с запросами"
versionInfo извлекается из <p class="V8SH_versionInfo"> — проверка совместимости платформы
Алиасы генерируются Вариантом B: title вес 1.0/1.2, heading вес 0.7/0.9, биграммы внутри каждого источника отдельно
Стоп-слова для BSL отключены — все слова > 2 символов участвуют в генерации алиасов
Путь к файлам всегда задаётся в задании — не зафиксирован, может быть любым
Структура папок произвольная — пример приведён только как ориентир
search_aliases НЕ СУЩЕСТВУЕТ — используется alias_targets с полями groups_id, snippets_id, weight
