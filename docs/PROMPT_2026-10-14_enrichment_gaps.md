Содержимое макета СКД недоступно ни одному из 16 инструментов:

|---|---|---|

Причина отсутствия авто-сниппетов — `src/enrichment_generator.py:81`:

```python
re.compile(r"<[A-Za-z0-9_:.-]*queryText[^>]*>(?P<sql>.*?)</[A-Za-z0-9_:.-]*queryText>", re.DOTALL)
```

в схеме компоновки данных запрос датасета лежит в `<query>` (без суффикса `Text`), поэтому регулярка
его не находит. Вывод: анализ макета (текст `<query>`, вычисляемые поля, `dataSetLink`,
отключённые параметры) сегодня возможен только чтением файла выгрузки — то есть нарушением правила
№ 2. Узлы C, A, B устраняют это по нарастающей: перенос знания в БД → автоматический разбор →
инструмент чтения.

## 8. Подводные камни (проверено)

- `validate_load_flow.py --with-load`, `validate_external_children.py`,
  `validate_enrichment_flow.py` очищают БД: `id` внешнего объекта меняются (история:
  271/272 → 275), актуальные — запросом `SELECT id, name FROM external_report ORDER BY id`;
  после валидаторов обязательны `tools/restore_reference_pair.py` + генерация + ручные алиасы +
  ссылки на документацию.
- Пустой jsonb-массив ≠ NULL: признак разобранного состава — `jsonb_array_length(items) > 0`;
  тип проверять через `jsonb_typeof` и `CASE` (`jsonb_array_length` падает на не-массиве).
- FTS `simple`: идентификаторы 1С не склоняются, префикс задавать явно —
  `to_tsquery('simple','слово:*')` (форма `'слово*'` оператор `*` теряет); подстрока — через
  `position()`; хвост/середина требуют `pg_trgm` (в кластере доступен, не установлен) или
  алиасов обогащения.
- Карточка объекта: счётчики разделов не зависят от `limit`, усечение перечня помечено строкой
  «всего N, показано M» — сверяться с числами `counts`, а не с числом строк в выводе.
- Правки Python-кода MCP-сервера требуют перезапуска процесса
  (`cd C:\1C_LLM\ckb; python server_configurations_enrichment.py`); правки документации и SQL —
  не требуют (`get_load_config_rules_tool()` читает файл при каждом вызове).
- Внешние объекты адресуются `uuid` или `source_path`; `config_id` в enrichment-инструментах нет
  и не появится.
- Ссылки `config_cross_references` — односторонние (в `local_doc` ответной строки нет), внешнего
  ключа нет (другая база, FDW не поднят): целостность проверяет `add_config_cross_reference_tool`,
  при чтении каждая строка помечается `ok`/битая. Обратная навигация «API → объекты выгрузки»
  работает через `get_config_cross_references_tool(local_doc_id=…)` — это и есть рабочая ценность
  механизма, а не счётчик `doc_links`.
