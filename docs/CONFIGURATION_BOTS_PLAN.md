## 1. Норматив позиции и круг

Круг задают три ноги (правило V43, прецедент V52/V53/V54):

1. каталог `Bots/` — файл регистрации вида на объект (`Bots/<Имя>.xml`) и его подкаталоги;
2. записи индекса состава `ConfigDumpInfo.xml`: `Bot.<Имя>` (нога вида) и `Bot.<Имя>.Module`
   (нога модуля);
3. перечень заголовка `configurations.bots` (колонка `text[]`, заполнена стадией S2 узла V43).

| выгрузка | файлов регистрации | каталогов содержимого | строк индекса вида | строк индекса детей | перечня заголовка |
|---|---|---|---|---|---|
| MinCfg | 2 | 2 | 2 | 2 | 2 |
| KomMag | 0 | 0 | 0 | 0 | `NULL` |
| BGU2 | 0 | 0 | 0 | 0 | `NULL` |
| BP3 | 0 | 0 | 0 | 0 | `NULL` |
| **итого** | **2** | **2** | **2** | **2** | **2** |

Все три ноги совпадают там, где вид есть: `file_only` / `index_only` / `header_only` — пусто;
uuid файлов совпадают с uuid индекса у 2 имён из 2; пустых uuid в файлах нет; повторных имён в
индексе нет. Нули названы, а не подразумеваемы: у трёх выгрузок вида нет ни одной из трёх ног, и
это состояние выгрузки, а не отказ загрузки (прецедент Q9 узлов V48/V50/V52/V53).

Раскладка содержимого одна и та же у обоих объектов: единственный файл `<Имя>/Ext/Module.bsl`
(расширение только `.bsl`). Каталогов `Forms/`, `Templates/`, `Commands/`, `Ext/Help/` и других
файлов у вида **нет ни в одной выгрузке** — то есть вид не касается таблиц `forms`, `form_ext`,
`templates`, `commands`. Блока `<ChildObjects>` нет ни в одном файле регистрации: дети вида
описаны только индексом состава (2 записи `Bot.<Имя>.Module`).

### 1.2 Дочерние строки индекса состава: только модуль

Индекс состава даёт по одной дочерней записи на вид — `Bot.<Имя>.Module` с id
`<uuid вида>.1` (36 символов + суффикс; различение ног построено на форме id, а не на догадке).
Файл модуля подтверждён и файлом, и индексом: состояние `file_and_index` у 2 объектов из 2.

Тексты этих модулей уже лежат в БД: строки `bsl_modules` с
`parent_type = 'configuration_objects'`, `object_type = 'Bot'`,
`file_path = Bots/Бот1/Ext/Module.bsl` (186 симв.) и `Bots/Бот2/Ext/Module.bsl` (156 симв.),

«вид → слот модуля»). **Узел V55 эти тексты не читает и не перезаписывает**: он называет файлы
дескрипторами и состоянием ног (прецедент Q8 узлов V51/V52), а тексты принадлежат стадии S4b.

### 1.3 Общий uuid и общее имя вида между конфигурациями (M1) — замер с границей

Замер `_v55_m1_probe.py`:

* внутри `MinCfg` коллизий нет: 2 файла дают 2 различных uuid и 2 различных имени, повторных
  имён в индексе нет;
* кросс-выгрузочно: **0 uuid** и **0 имён** встречаются в двух и более выгрузках — потому, что
  вид есть только в одной выгрузке корпуса;
* по корпусу 2 файла дают 2 различных uuid и 2 различных имени.

Граница называется прямо: корпус не даёт доказательства ни одной коллизии, но и не опровергает
их — в `BGU2`/`BP3` объектов `Bot` нет (то же зафиксировано замером V43: виды `Bot`, `Interface`,
`WebSocketClient` отсутствуют в обеих полных выгрузках). Границы ключа всё равно держат границу
конфигурации: перечень заголовка хранит детей массивом **имён** (`configurations.bots`), поэтому
ключ по одному `object_uuid` или одному имени этим корпусом не проверяется и взят по прецеденту
V52/V53/V54 (там 15 / 162 / 134 общих uuid на пару конфигураций).

## 2. Словарь свойств узла вида (замер `_v55_p0_probe.py`)

Файл регистрации — `MetaDataObject` версии `2.20` (namespace `http://v8.1c.ru/8.3/MDClasses`),
узел вида `<Bot uuid="…">`, верхний уровень узла — ровно один блок `Properties` (2 файла из 2).
Словарь тегов и ФОРМЫ значений:

| тег | в файлах | формы значений |
|---|---|---|
| `Name` | 2 | `scalar` ×2 |
| `Synonym` | 2 | `multilang` ×2 (`v8:item`/`v8:lang`/`v8:content`) |
| `Comment` | 2 | `scalar` ×2 |
| `Predefined` | 2 | `bool` ×2 |
| `Picture` | 2 | `block` ×2 (`xr:Ref` + `xr:LoadTransparent`) |

Итого 5 имён тегов по 2 файлам. Пустых `Comment` — 0, файлов без `Synonym` — 0, битых файлов — 0.
Значений `xsi:nil` нет.

**Словарь не замкнут.** Он построен по 2 файлам одной выгрузки; XSD вида нет (раздел 1.5); в двух
других полных выгрузках объектов вида нет вовсе. Какими ещё свойствами платформа описывает бота в
реальной конфигурации, корпус не отвечает — ни один из доступных источников (четыре выгрузки,
`xsd-schemas/`, слой знаний `local_doc` по запросу о свойствах вида) этого не измеряет. Поэтому
узел не додумывает имена: словарь держится закрытым по замеренным пяти тегам, а всё, что встретится
в другой выгрузке, обязано остаться значением с состоянием `unknown_tag` / `unknown_value` и именем
виновника (прецедент Q7 узла V50), а не отказом записи и не молчаливым пропуском. Это и есть
решающая развилка узла — Q1 раздела 6.

### 2.1 `Picture` — блок ссылки с двумя разными классами цели

Единственное свойство вида, несущее ссылку. Форма одна: блок `<Picture>` с двумя дочерними
элементами — `xr:Ref` (значение — адрес ссылки) и `xr:LoadTransparent` (булево). Замер по 2 файлам:

| элемент | значение | состояние по индексу состава |
|---|---|---|
| `xr:Ref` | `CommonPicture.ОбщаяКартинка1` | `exact` — запись есть в индексе `MinCfg` |
| `xr:Ref` | `StdPicture.GroupConversation` | индексом **не разрешается** |
| `xr:LoadTransparent` | `true` | значение флага, не ссылка |

Различие принципиальное: `CommonPicture.` — ссылка на объект конфигурации (его слой не загружен,
позиция 2.19 нормативного списка), `StdPicture.` — стандартное средство платформы, которого ни в
индексе состава, ни в выгрузке быть не может. Поэтому разрешение ссылки — не бинарное
`exact`/`unresolved`, а закрытый словарь классов цели (`exact` / `std_picture` / `unresolved` /
`empty_value` / `absent`), и внешнего ключа ссылка не заводит: цель не утверждается (прецедент Q3
узлов V50/V52/V53).

### 2.2 Модуль вида: файл и строка индекса есть, тексты принадлежат V47

Слот `Module` у `Bot` закрыт узлом V47 — две строки `bsl_modules` в живой БД (раздел 1.2). Узел
V55 оперирует дескрипторами: путь, размер, состояние двух ног (`file_and_index` / `index_only` /
`file_only` / `absent`). Других слотов модуля у вида нет: `Ext/` содержит только `Module.bsl`,
форм и командных модулей в корпусе ноль.

### 2.3 Значения флагов

`Predefined` — `true` у одного объекта, `false` у другого (оба значения даны корпусом, словарь
булевых замкнут для этого тега). Значение флага не утверждается как свойство объекта для целей
поиска — прецедент O1 узла V49 («значение права не читается как правомочие»); здесь оно
сохраняется как есть.

## 4. Модель A–H: что поставил замер (правка — шаг П7)

Позиция 2.10 относится к группе **E «Объекты без дочерней структуры — только свойства»** модели
`docs/config-scenarios/01_configuration.md`: файл регистрации несёт только блок `Properties`,
блока `<ChildObjects>` нет, каталогов форм/макетов/команд ноль. Строка группы E перечисляет
незакрытые позиции — `Bots` среди загруженных не назван, и закрытие 2.10 её и правит.

Две другие группы затрагиваются замером, но не этим узлом:

* **группа A (общая раскладка детей)** — в перечне видов группы A каталог `Bots/` назван
  (строка модели перечисляет `Bots/` среди объектов с общей раскладкой). Замер показывает, что
  из детей общей раскладки у вида есть **только модуль**; реквизитов, табличных частей, форм,
  макетов и команд — ноль строками (раздел 1.1). Формулировка «объекты с общей раскладкой» для
  этого вида неверна в части детей и правится шагом П7 той же формулировкой, что уже применена к
  `FilterCriteria` (узел V52) и `EventSubscriptions` (узел V53);
* **группа B (модули)** — слот `Module` вида закрыт узлом V47, и узел V55 его не трогает
  (раздел 2.2). Строка группы B правкой V47 уже приведена к фактическому состоянию.

Группа F (специфичная структура вида) к позиции не относится: содержимого со своей схемой у вида
нет — файл `Ext/Module.bsl` является модулем группы B, а не содержимым вида.

## 5. Что следует из замеров до кода (M1…M7)

* **M1 — ключ обязан включать границу конфигурации.** Доказательства коллизий корпус не дал
  (раздел 1.3), но перечень заголовка хранит детей массивом имён, а прецеденты V52/V53/V54
  показали коллизии у трёх других видов. Ключ версионности строки вида —
  `(configuration_uuid, object_name, revision_no)`, `object_uuid` — отдельная колонка и поисковый
  индекс (правило 4 карточки `rules:core-rules:functional:add-object-block`).
* **M2 — метка времени одна на загрузку.** Конвейер передаёт единый `changed_at` всем стадиям
  (мера M2 узлов V50–V54); одиночный вызов — свою.
* **M3 — строка одна на файл, второй таблицы нет.** У вида нет ни содержимого со своей схемой, ни
  детей общей раскладки, поэтому узел — одна таблица вида; таблиц-детей, как у V51/V52/V54, нет.
* **M4 — ссылка `Picture` обязана различать классы цели** (раздел 2.1): `CommonPicture.`
  разрешается индексом состава, `StdPicture.` индексом не разрешается никогда. Запись состояния
  одна на строку вида; внешнего ключа нет.
* **M5 — модуль вида уже в БД, и его нельзя трогать дважды.** Строки `bsl_modules` пишет V47;
  стадия V55 обязана не снимать и не перезаписывать их (иначе повторная загрузка позиции 2.10
  снимет чужие строки), а состояние ног называть отдельными колонками.
* **M6 — отсутствующий каталог вида и `NULL` перечня заголовка — состояния, а не отказы**
  (раздел 1.1, раздел 3): три из четырёх выгрузок не имеют вида ни одной ногой.
* **M7 — словарь свойств открыт фактически** (раздел 2): узел обязан держать механизм
  `properties_state` + `unknown_property_names`, уже реализованный в таблицах V53/V54, и не
  превращать незнакомый тег в отказ.

  не загружен, `StdPicture.*` индексом не разрешается осознанно (раздел 2.1, Q3);
