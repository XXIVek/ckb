## АЛГОРИТМ ПРИНЯТИЯ РЕШЕНИЙ ПРИ ПОИСКЕ

### Шаг 1: Определение типа запроса

| Тип запроса | Пример | Что искать первым |
|-------------|--------|-------------------|
| Конкретный метод/функция | Как создать Справочник, Метод Random() | `search_docs_tool("Справочник")` |
| Пример кода/решение | Обработка исключений, HTTP-запрос | `search_docs_tool("обработка исключений")` |
| Общая информация | Что такое регистр | `search_docs_tool("регистр")` |

### Шаг 2: Приоритет поиска (внутри search_docs_tool)

1. **Поиск по алиасам (rank 3.0):** Точное совпадение LOWER(alias_name). Алиасы, привязанные напрямую к `snippets_id` без группы, получают приоритет rank=3.0 > групповых (rank=2.0)
2. **Full-text поиск по groups (rank 1.0):** Ищет по `name || pagetitle`. **heading НЕ участвует!**
3. **Full-text поиск по snippets (rank 0.5):** Ищет по `question || answer`
4. **Результаты сортируются по rank DESC**, limit применяется в конце.

### Шаг 2b: что именно возвращает поиск (критично для вывода)

`search_docs_tool` возвращает **список найденных строк: тип, ID, заголовок и превью в 200
символов** (`src/mcp_tools_api.py::search_docs`, поля `title[:200]` и `description[:200]`).
Полного содержимого в выдаче нет ни у групп, ни у сниппетов — это намеренно: `groups.description`
хранит весь `<body>` HTML, ответ ручного сниппета доходит до десятков килобайт.

Отсюда правило чтения результатов:

| Тип строки | Как получить содержимое | Статус |
|---|---|---|
| группа (`type=group`) | `get_doc_tool(doc_id)` — `pagetitle`, `title`, `heading`, `versionInfo`, `description` | работает |
| сниппет (`type=snippet`) | **нечем**: инструмента чтения сниппета по ID в контракте `server.py` нет | открытый дефект (см. ниже) |

Пока дефект не закрыт, содержимое сниппета по ID читается только в скриптах-валидаторах и
SQL-сверках, которые оператору не отвечают. Утверждать по превью в 200 символов, что говорит вся
строка, — значит выдавать недоказанное: в выдаче видно начало, а не словарь значений, не таблицу
и не вывод. Если вывод зависит от содержания, а прочитать его нечем — это надо сказать прямо.

### Шаг 3: Интерпретация результатов

Если найдены группы:

1. Проверяем tags — категория документа (language, platform, bsl, methodology, its, xml-format)
2. Смотрим pagetitle — официальное название из документации
3. Получаем полный HTML-контент страницы инструментом `get_doc_tool(doc_id)`, а не по превью
4. Проверяем versionInfo — с какой версии доступно

Если найдены сниппеты:

1. **Проверяем groups_id:**
   - `groups_id IS NOT NULL` → сниппет привязан к BSL-группе, полный контекст группы берётся
     из `get_doc_tool(doc_id)` этой группы
   - `groups_id IS NULL` → сниппет без группы (PDF, ручные, слой `xml-format`), контекста группы
     нет, и содержимое строки недоступно ничем, кроме как описано в Шаге 2b
2. Смотрим confidence — уверенность извлечения кода (0.5-1.0)
3. Анализируем question — контекст использования (он отдаётся целиком в пределах 200 символов)
4. **Содержимое сниппета (`answer`) из выдачи поиска не берётся**: там только превью. Вывод о
   содержимом делается либо по полному тексту, полученному вне поиска (скрипт-валидатор,
   SQL-сверка), либо не делается вовсе

## ИСПОЛЬЗОВАНИЕ MCP-ИНСТРУМЕНТОВ

### 0. Правила поиска (Шаг 0 перед поиском)

```python
get_search_rules_tool()   # текст этих правил; перезапуска сервера не требует, читается при каждом вызове
get_load_rules_tool()     # правила загрузки документов в базу
```

Шаг 0 нужен потому, что механика поиска неочевидна: алиасный шаг работает только по точному
совпадению, а выдача содержит превью, а не содержимое. Текст правил обязан совпадать с кодом —
это сторожит `python tools/check_search_rules_sync.py` (шаг 9 `validate_project.py`).

### 1. Комбинированный поиск (основной метод)

```python
search_docs_tool(query="Справочник", category=None, limit=20, include_marked=False)

# Категории: language / platform / its / methodology / xml-format (одна или несколько через запятую)
# Возвращает: строки [type, id, title, description-превью, rank] — и группы, и сниппеты
# Когда использовать: всегда — это основной инструмент поиска.
# ВАЖНО: запрос совпадает с алиасом только целиком (см. «Приоритет поиска»). Многословный
# запрос не может попасть в алиасный шаг и уходит в полнотекстовый с rank 0.5–1.0.
```

### 2. Получение полной группы

```python
get_doc_tool(doc_id=61083)
# Возвращает: ID, Название, pagetitle, title, versionInfo, tags, description (HTML body)
# Содержимое сниппета по этому инструменту не читается: он работает только по таблице groups.
```

### 3. Состояние БД

```python
get_db_state_tool()
# Возвращает: groups / snippets / aliases / snippets_marked_for_deletion — живые числа.
# Разбивку сниппетов по происхождению печатает python tools/count_snippet_breakdown.py.
```

### 4. Список категорий

```python
list_categories_tool()
# Возвращает: language / platform / its / methodology / xml-format с честными счётчиками по каждой
```

## ПРАВИЛА ИНТЕРПРЕТАЦИИ РЕЗУЛЬТАТОВ

### 1. Ранжирование результатов

Фактор	Вес	Описание
rank (из поиска)	высокий	Результат full-text поиска по relevance
pagetitle совпадение	высокий	Точное совпадение = лучший результат
confidence сниппета	средний	confidence > 0.8 = качественный код
tags: bsl	высокий	Документация BSL — приоритетный источник

### 2. Обработка пустых результатов

Если `search_docs_tool` вернул «Результатов не найдено»:

1. Проверить, что запрос — **один термин в точной форме алиаса**, а не словосочетание: алиасный
   шаг сравнивает `LOWER(alias_name)` со всем запросом целиком.
2. Попробовать другую форму того же термина: с косой чертой и без (`/DumpIB` и `DumpIB` — разные
   алиасы), латиницу вместо кириллицы (`ubound`, а не `убound`), имя свойства XML — точное
   (`DefaultRunMode`, а не «режим запуска»).
3. Снять категорию и повторить без неё: пустой ответ **с категорией** означает «в этой категории
   термина нет», а не «знания нет в базе».
4. Если термина нет ни в одной форме — это **отсутствие алиаса**, то есть незнание в базе, а не
   неудачный запрос. Лечится записью знания и его алиасов (`add_snippet_tool`,
   `add_aliases_tool`), а не перебором запросов.

### 3. Работа с HTML-контентом

description содержит ВЕСЬ body HTML:

Может включать ссылки, таблицы, стили
Для AI: полезен для понимания контекста
Для пользователя: извлекать только текст (убрать теги)

### 4. versionInfo

Если group[versionInfo] не пустой:

Использовать для проверки совместимости
"Доступен, начиная с версии 8.0" = минимальная версия платформы

## ⚠️ ЧАСТЫЕ ОШИБКИ И КАК ИЗБЕЖАТЬ

Ошибка: Использование таблиц search_aliases / docs / doc_fragments
Эти таблицы НЕ СУЩЕСТВУЮТ! Использовать alias_targets и groups.

Ошибка: Поиск только по name
search_docs_tool ищет по: name || pagetitle (groups) + question || answer (snippets). heading НЕ участвует в full-text поиске — только для генерации алиасов.

Ошибка: Игнорирование category
Если знаете категорию — всегда указывайте:

search_docs_tool(query="HTTP", category="platform") — быстрее и точнее
search_docs_tool(query="Random", category="language,bsl") — BSL-функции

Ошибка: Не проверка versionInfo
Всегда проверяйте versionInfo для совместимости!

Ошибка: Понимание группировки сниппетов
Сниппеты без groups_id (NULL) не связаны с группами. Они ищутся только по алиасам или full-text поиску. При поиске алиаса такие сниппеты получают приоритет rank=3.0.

Ошибка: Использование русских символов для алиасов
Алиасы генерируются из ASCII (pagetitle/heading). Используйте "ubound", а не "убound".

Ошибка: Считать, что содержимое сниппета видно из выдачи поиска
Выдача содержит превью в 200 символов. Утверждать по нему о словаре значений, таблице или выводе
— значит выдавать недоказанное. Содержимое группы читается `get_doc_tool(doc_id)`; содержимое
сниппета по ID не читается ничем (открытый дефект контракта `server.py`), поэтому вывод о полном
тексте сниппета делается либо по замеру вне поиска, либо не делается.

Ошибка: Искать термин, которого нет среди алиасов, и считать это «знания нет»
Находимость строки в категории создаётся её алиасами: строка без алиаса в этой категории для
поиска не существует. Карточка знания без алиасов (XML-имя, имя колонки БД, русская формулировка)
считается незаписанной, даже если текст в базе есть.

Ошибка: Писать число сниппетов, алиасов или категорий без замера
Число без даты и без имени инструмента (`get_db_state_tool()`, `list_categories_tool()`,
`tools/count_snippet_breakdown.py`) устаревает молча — текст правил 07.10.2026 держал счётчики
ниже живых и четыре категории вместо пяти.

Ошибка: Делать вывод о знании по одному источнику, не прочитав его
Если найденные строки противоречат друг другу (например, разные словари значений одного свойства),
противоречие надо назвать и разрешить по авторитетному источнику (группа BSL-документации), а не
выбрать ту строку, которая первая попала в выдачу.
